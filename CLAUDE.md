## Build Commands

This is a .NET 9 class library with integration tests. The solution file is `SqlSchemaHasher.sln` at the repo root.

```bash
dotnet build SqlSchemaHasher.sln
dotnet test SqlSchemaHasher.sln
dotnet pack src/zachtbeer.SqlSchemaHasher.csproj -c Release
```

Integration tests use Testcontainers to spin up SQL Server 2025 in Docker. Docker must be running to execute tests.

## Architecture

This library computes deterministic SHA256 hashes of SQL Server database schemas for change detection and environment comparison. It is published as the `zachtbeer.SqlSchemaHasher` NuGet package.

### Core Flow

`SqlSchemaHash` (static facade) → `SchemaExtractor` (SQL queries via Dapper) → `SchemaMetadata` (immutable records) → `SchemaHashCalculator` (deterministic SHA256)

### Key Classes

- **`SqlSchemaHash`** — Static public API. All consumer-facing methods live here. Returns base64-encoded hashes (hex internally, converted at the boundary).
- **`SchemaExtractor`** — Runs batch queries against `sys.*` catalog views to extract tables, stored procedures, and user-defined table types. Object exclusion comes from `ObjectNamesToIgnore` plus, when `IgnoreSysDiagramObjects` is set, the SSMS diagram object names (additive union). Schema filtering (`SchemaFilter` option) is applied in-memory after extraction. Index key columns carry " DESC" suffixes for descending keys; `IndexSchema.KeysWithoutDirection` holds the direction-free variant (null when identical to `Keys`).
- **`SchemaHashCalculator`** — Streams schema elements into `IncrementalHash` (SHA256). Strings are length-prefixed to avoid hash collisions. Indexes are projected to their *effective* (post-normalization) values via `GetEffectiveIndex` and sorted by those effective values before hashing, so option-equivalent databases hash identically. `IsAutoGeneratedName` detects SQL Server system names (`PK__Table__<hex>`) and GUID-suffixed names; under `NormalizeAutoGeneratedIndexNames` they hash as an empty-string sentinel.
- **`SchemaMetadata`** — Immutable record types representing the schema. All schema objects are schema-qualified (`[schema].[name]`).
- **`SchemaHashOptions`** — Comparison settings with static presets: `V1` (v1 semantics, sort order ignored), `V2` (recommended; `Default` is an alias), `Structural` (ignores index names, constraint names, clustering type, key sort order). Individual settings: `SchemaFilter`, `ObjectNamesToIgnore`, `IgnoreSysDiagramObjects`, `NormalizeAutoGeneratedIndexNames` (sentinel-based), `IgnoreIndexNames` (wins over normalize), `IgnoreConstraintNames`, `NormalizeClusteringType`, `IgnoreIndexSortOrder`, `IncludeStoredProcedureText`. Bare `new SchemaHashOptions()` is the neutral everything-exact baseline.

## Code Style

- Function parameters, constructor arguments, and record definitions should always be on a single line. Do not wrap parameters onto multiple lines.

### Important Details

- `SchemaExtractor.BuildIndexDescription` preserves the actual index type (e.g., `clustered`, `nonclustered`). The `NormalizeClusteringType` option in `SchemaHashCalculator` controls whether these are normalized to `x-clustered` for comparison.
- Stored procedure body hashing uses SQL Server's `HASHBYTES('SHA2_256', ...)` server-side rather than transferring procedure text.
- The hash output path: `SchemaHashCalculator` produces lowercase hex → `SqlSchemaHash` converts hex to bytes then to base64 for the public API.
- Dependencies: `Dapper` for queries, `Microsoft.Data.SqlClient` for SQL Server connectivity.
