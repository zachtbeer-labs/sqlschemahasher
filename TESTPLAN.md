# SqlSchemaHasher — Settings Test Map & Prioritized Recommendation

This document maps the full `SchemaHashOptions` settings surface to a comprehensive,
value-sorted integration-test plan. It is the checklist for the coverage-audit pass
(map each row to an existing test, mark gaps) and the build order for new tests.

> Status legend used below: `✓` fully covered today, `✓ partial` partially covered,
> (blank) not yet audited / assumed missing. Audit pass fills these in.

---

## B. The canonical contract every loosening bit must satisfy

Rather than test arbitrary combinations, each of the 22 normalization bits is proven
against the same **4-part contract**. This is the reusable shape (mirrors what
`PresetAndNormalizationTests` already does ad-hoc):

- **T1 — Sensitivity:** two DBs differing *only* in the facet → **different** hash under
  bare `new SchemaHashOptions()` (Strict baseline).
- **T2 — Collapse:** same two DBs → **equal** hash with the bit set.
- **T3 — Specificity (anti-over-collapse):** with the bit set, a genuine difference in a
  *sibling* facet of the same object still → **different** hash. *(Most-skipped and
  highest-value-per-effort guard — proves a bit removes exactly one distinction, the
  enum's stated invariant.)*
- **T4 — Surface coverage:** the bit fires on **every** surface it claims:
  - enforcement bits (`Constraints.Ignore{Disabled,Trust,NotForReplication}`) → **FK and CHECK**
  - identity bits (`Tables.IgnoreIdentity*`) → **tables and table types**
  - index/constraint name bits → a **PK** (surfaces as *both* an index name and a key-constraint name)

Full "obvious permutation" universe ≈ 22 bits × (T1+T2+T3) + surface fan-out
≈ **75–85 focused tests**, plus ≈ **20 structural/meta/scoping** tests.
**Comprehensive total: ~95–105 tests. Strong core (P0+P1+P2): ~35–40 tests.**

## D. Recommendation

**Build order: P0 → P1 → P2, then P3, then P4/P5.**

- **P0 (4 tests)** — highest leverage per line: golden anchors turn *any* silent hash
  drift into a red test, which is the entire point of a hashing library. Do these first,
  even before auditing existing coverage.
- **P1 (9 contracts ≈ 20–25 tests)** — every option a user realistically sets to suppress
  a false-positive diff. Prioritize the **T3 specificity** halves — most likely missing
  today, and they prove each bit removes *exactly one* distinction.
- **P2 (7 tests)** — protects subtle documented behaviors (name precedence,
  `is_system_named` vs heuristic divergence, preset composition) that a refactor would
  break without any compile error.
- **P3–P5** — complete the matrix; the physical-index and identity-on-table-type
  contracts are the notable current blind spots.

**Estimated comprehensive total: ~95–105 tests. Defensible core (P0+P1+P2): ~35–40 tests.**

### Structural suggestions for implementation

1. **Parametrized triad helper** — `AssertBitContract(makeDbA, makeDbB, bitOptions, siblingDbB)`
   with `[DataRow]` so the 22 bit contracts are data, not 75 copy-pasted methods. Also
   makes the audit a mechanical bit → covered/uncovered mapping.
2. **One shared rich reference fixture** for all golden/independence tests, built once per class.
